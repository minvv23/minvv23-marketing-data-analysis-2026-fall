## 1. 요청과 방향

### 1.1 요청 순서

1. 발제 논문과 관련해 staggered DID 논의를 Codex 웹검색으로 더 조사. 결과는 후속 논의 문서로 정리했다.
2. 9월 발제 슬라이드(`20260909-presentation.html`)의 형식을 따르되, 다른 프로젝트의 시행착오와 기법으로 크게 고도화.
3. 논문에 없는 내용을 더하기보다 **논문에 있지만 통계적 직관이 까다로운 부분을 시각적으로 보여 주고 비교하는 데 집중**.
4. 참고 자료로 manim, 3brown1blue 저장소와 Knowledge Warehouse의 AI식 웹디자인, AI식 한국어 표현 문서를 지정.
5. 질문형 제목은 "~는가, ~인가" 대신 "~일까?, ~걸까?" 말투.
6. 마지막 장의 토론 문항 세 개는 불필요.
7. 통계 용어를 Codex 웹검색으로 조사해 한국어에서 자연스럽게 쓰는 표현으로 교체.
8. 문구가 앞뒤 맥락이 잘린 AI식 말투라는 지적. `AI식-한국어-표현.md`를 직접 읽고 전 장의 리드와 단계 문구를 다시 씀.
9. 논문 발제이므로 일반적인 방법론 해설보다 **논문이 직접 다루는 내용**에 대한 장을 더 추가 (11-14). 원문을 절 단위로 덱과 대조해 일곱 장을 더했다. 3.1절에 정리했다.
10. 논문 원문을 보지 않고 발표자료만 보아도 이해할 수 있게 조금 더 친절하게 (11-14). 논문을 읽지 않은 사람 기준으로 전 장을 다시 읽고, 풀이 없이 나오던 용어와 약어 27곳에 마우스를 올리면 뜨는 설명을 붙였다 (Compustat, ROA, Tobin's Q, BLL, FHLT, 사전추세, CATT, 사건창, IPW, 이중강건, 비교집단의 세 종류 등). 왼쪽 글에 여유가 있는 장에는 첫 등장에 짧은 풀이를 넣었다 (시차 도입, 2×2 DID, 제1종 오류, 분해식의 세 항). 분해식의 VWATT, VWCT, ΔATT는 KaTeX의 `\htmlData`로 수식 항에 직접 설명을 달았다.
11. 설명 대본을 웹과 연계해서 (11-14). 장과 단계마다 말할 내용을 `_src/20261118/notes.md`에 쓰고 (142꼭지, 1분 320자 기준 약 35분), 빌드가 이것을 덱과 [발표 대본 문서](20261118_발표대본.md)에 함께 넣는다. 덱에서는 N 키로 화면 아래에 대본을 띄우고, P 키로 발표자 화면을 새 창에 연다. 두 창은 `postMessage`로 상태를 주고받아서 `file://`로 열어도 동작한다. 발표자 화면 안의 작은 화면은 같은 파일을 `?embed`로 넣은 iframe이다. 헤드리스 크롬에서 팝업을 열어 양방향 넘김과 단독 실행을 확인했다.

### 1.3 "까다로운 직관"으로 고른 것과 보여 주는 방법

| 직관 | 장 | 보여 주는 방법 |
|---|---|---|
| DID가 빼는 것은 처치가 없었을 때의 변화여야 한다 | 3 | 비교집단의 변화 선분을 복사해 처치집단 출발점에 옮겨 붙인다 |
| 이미 처치된 집단을 비교집단으로 쓰면 효과 증가분이 빠진다 | 5 | 같은 동작을 다시 쓴다. E의 +8이 L의 반사실로 옮겨 가고 L의 실제 변화 2와의 차이가 −6 |
| 처치된 칸이 음의 가중치를 받는다 | 6 | 같은 여섯 칸의 숫자가 D, 예측값, 잔차 D̃, 가중치로 바뀐다. 예측값이 1을 넘는 칸이 음수가 된다 |
| 2×2의 가중치는 양수인데 계수는 왜 낮아지나 | 7 | 가로 가중치 × 세로 DID의 면적. 부호대로 더한 면적이 TWFE. U 단위 수를 바꾸면 면적이 변한다 |
| 언제 틀리고 언제 안 틀리나 | 8 | 같은 모의자료 500개에 효과만 바꿔 넣는다. 점 500개가 참값에서 멀어진다 |
| 어느 2×2가 문제인가 | 9 | 추정치(채운 표시)와 참 ATT(빈 표시)의 세로 거리 |
| 평균효과가 0이어도 유의하다 | 10 | t값 500개가 ±1.96 띠 밖으로 퍼진다 |
| 도입 전 계수가 오염된다 | 11 | −3기 계수가 실제로 싣는 칸을 달력 연도 격자에 표시 |
| 대안은 무엇을 바꾸나 | 12, 13 | CS는 (g,t)마다 2×2 테두리가 이동, stacked는 칸이 사건별 자료로 내려와 쌓인다 |
| 깨끗한 비교만 써도 평균이 다를 수 있다 | 13 | stacked의 가중치 막대 16/31 대 15/31 |

### 2.3 manim, 3brown1blue

- `3b1b/manim`: 기본 rate function `smooth(t) = 6t⁵ − 15t⁴ + 10t³`을 트윈의 기본 이징으로 썼다. `Transform`(현재 상태에서 다음 상태로 보간), `TransformFromCopy`(복사본이 옮겨 감), `ShowCreation`(선 그리기), `lag_ratio`(시간차 등장)를 SVG로 다시 구현했다.
- `christopherabey/3brown1blue`: LLM이 Manim 코드를 쓰게 하는 해커톤 앱이다. 설계 지침은 프롬프트 두 개뿐이라 가져올 것이 적었다 (겹치지 않게, 화면 안에, 마지막에 전부 지우지 않기).
- `adithya-s-k/manim_skill`: "수식을 한꺼번에 보여 주지 않는다", "관련된 것은 지웠다 새로 띄우지 말고 변형한다", "색은 의미이고 끝까지 유지한다", "빠르게 깔고 핵심에서 천천히"를 참고했다.

- 계속 움직이는 장식은 없다.

**문구.**

- 질문형 제목은 "~일까?, ~을까?". 나머지 제목은 평서문.

- 격식 치환: 쓰다 → 사용하다, 빼다 → 차감하다 또는 제외하다, 넣다 → 포함하다, 풀다 → 해제하다 또는 완화하다, 오르다 → 상승하다, 줄다 → 감소하다, 모이다 → 집중되다 또는 분포하다, 뽑다 → 추출하다, 깨지다 → 위반하다.

**맥락을 살린 문장.** 처음 문구는 "분해. 이미 완화한 주를 …", "반대 자료. 효과는 0이고 …"처럼 명사 머리말 뒤에 단문을 나열했다. 기계 점검은 통과했지만 "앞뒤 맥락이 잘린 AI식 말투"라는 지적을 받았다. 전 장을 다음 기준으로 다시 썼다: 리드의 첫 문장으로 앞 장과 잇는다, 명사 머리말을 문장 안의 주어로 넣는다, 문장 사이의 이유를 연결어미로 적는다, 논문이 한 일은 주어를 밝혀 과거형으로 쓴다, 곁말은 괄호에 넣는다. 고친 뒤 화면 문장 219개의 평균 길이는 55자다.

### 5.1 트윈 (engine.js)

도식의 모든 요소는 처음에 한 번 만든다. 렌더러는 단계 번호를 받아 **목표값만** 정한다. `tw`가 요소마다 현재값을 기억하고 있다가 목표값까지 이어서 움직인다. 단계를 빠르게 넘기면 움직이던 자리에서 새 목표로 방향을 바꾼다.

```js
function tw(el, props, o) {
  o = o || {}; const dur = o.dur ?? 650, delay = o.delay || 0, ease = E[o.ease || 'smooth'];
  const s = el.__s || (el.__s = {}); let m = ACT.get(el);
  for (const k in props) {
    const to = props[k];
    if (!(k in s) || !LIVE) { s[k] = to; put(el, k, to); if (m) m.delete(k); continue; }   // 처음이거나 즉시 모드
    const cur = m && m.get(k);
    if (cur ? same(cur.to, to) : same(s[k], to)) continue;                                  // 이미 그 값이거나 가는 중
    if (!m) { m = new Map(); ACT.set(el, m); }
    m.set(k, { to, from: null, t0: performance.now() + delay, dur, ease });                 // from은 시작 순간에 읽는다
  }
  if (!raf && ACT.size) raf = requestAnimationFrame(frame);
  return el;
}
```

특수 속성: `o`(불투명도, 0이면 `visibility:hidden`), `tx ty sc rot`(변환), `pts`(점 배열을 path의 d로), `draw`(0~1 선 그리기, `pathLength=1`), 색(hex 보간). `LIVE`가 꺼진 즉시 모드는 캡처와 뒤로 넘김에 쓴다.

### 5.3 계산 코어 (stats.js)

균형패널에서 설명변수는 코호트와 시점으로만 정해진다. 그래서 단위 고정효과가 있는 OLS 계수는 **코호트×시점 평균만으로** 계산된다. 자료를 `[{n, g, y[]}]`(단위 수, 도입 시점, 평균 경로)로 다룬다.

```js
ST.twfe = function (groups, T) {
  const w = groups.map(g => g.n);
  const D = groups.map(g => Array.from({ length: T }, (_, t) => treated(g, t)));
  const Dt = demean(D, w, T);                          // D - 단위 평균 - 시점 평균 + 전체 평균
  let num = 0, den = 0;
  groups.forEach((g, k) => { for (let t = 0; t < T; t++) { num += w[k] * Dt[k][t] * g.y[t]; den += w[k] * Dt[k][t] * Dt[k][t]; } });
  const cellw = Dt.map((r, k) => r.map(v => w[k] * v / den));   // 칸별 가중치. 처치된 칸의 합은 1
  return { delta: num / den, D, Dt, den, cellw };
};
```

- `ST.bacon`: Goodman-Bacon (2021)의 가중치 공식 세 가지(처치 대 미처치, 먼저 대 나중, 나중 대 먼저)와 2×2 DID. 가중합이 TWFE와 같은지 테스트한다.
- `ST.eventDesign`: 상대시간 더미를 이중 평균제거하고 정규방정식을 풀어 둔다. 같은 설계로 여러 결과를 빠르게 추정한다.
- `ST.attgt`, `ST.aggEvent`, `ST.aggStatic`: 공변량 없는 CS식 2×2와 집계.
- `ST.stacked`, `ST.stackedEvent`: 사건별 자료를 만들고 자료별 고정효과로 쌓아 추정.

### 5.4 시뮬레이션 (simcore.js)

모든 추정량이 결과에 대해 선형이므로 **추정치 = 효과 부분 + 잡음 부분**으로 나눈다. 잡음 500벌은 한 번만 뽑아 여섯 설정이 함께 쓴다. 그래서 8장에서 Sim을 바꾸면 같은 점 500개가 이동한다.

```js
const est = sim => { const d = twNoise[desOf(sim)], e = twEff[sim]; return d.map(v => (v + e) / SIG); };
```

제1종 오류 장의 군집 t값도 같은 방식이다. 주별 점수가 기울기 τ에 대해 선형이라 이질성 41단계 × 500벌을 20ms 안에 계산한다.

```js
function tstats(h) {
  for (let i = 0; i < NSIM; i++) { const tau = z3[i].map(z => z * h * SIG); let sum = 0; const A = new Float64Array(NST);
    for (let s = 0; s < NST; s++) { A[s] = aC[i][s] + tau[0] * bC[0][s] + tau[1] * bC[1][s] + tau[2] * bC[2][s]; sum += A[s]; }
    const d = sum / den; let v = 0; for (let s = 0; s < NST; s++) { const sc = A[s] - d * dC[s]; v += sc * sc; }
    out[i] = d / Math.sqrt(N / (N - 1) * v / (den * den)); }                     // 주 단위 군집 표준오차
  return out;
}
```

설정: 50개 주, 1980-2015년, 주-연도 평균 잡음의 표준편차 0.036 (Sim 1의 추정치 표준편차가 원문과 비슷한 0.011σ가 되게 맞춤), 시드 20261118.
