# 독해가이드 이해 보강 규격 (2026-11-17, 보강 작성자용)

## 0. 왜 하는가

사용자(이 가이드의 독자, 11/18 발표자)는 OLS와 2×2 DID의 아주 기초적인 개념만 안다. 가이드를 읽다가 다음 같은 곳에서 막혔다고 직접 짚었다(모두 1부 FWL 절, 조립자가 이미 고쳤다).

1. FWL 정리를 말로만 적어서 수식이나 그림으로 보이지 않았다.
2. `δ̂ = ΣD̃Y / ΣD̃²`가 어떻게 유도되는지, 왜 Y의 잔차 대신 Y를 써도 되는지가 한 문장으로 지나갔다. "항들이 이동하며 전개되는 것"을 보고 싶다고 했다.
3. `D̂`와 `D̃`가 무엇이 다른지, 실제 데이터 모양으로는 어떻게 생겼는지가 헷갈렸다. 수식의 각 기호에 마우스를 올리면 뜻이 나오면 좋겠다고 했다.
4. "직교하므로 ΣD̃D = ΣD̃²"에서 왜 직교하면 그 식이 성립하는지 몰랐다.

사용자 요청: **"비슷하게 내가 어려움을 겪을 포인트들이 아래에도 계속 나온다면 설명 추가, 화려하고도 엄밀한 JS 웹 테크닉 활용으로 보충자료 추가 등을 적극적으로 활용해서 더 빠르고 쉽게 이해할 수 있게 도와줘."**

공통 진단: 막히는 지점은 대부분 (가) 한 문장에 여러 단계를 압축한 유도, (나) 정의 없이 나온 기호, (다) "~이므로 ~이다"에서 이유가 OLS 기초 밖에 있는 경우, (라) 추상적인 서술을 실제 자료의 모양(표, 행과 열)으로 보여 주지 않은 경우다.

먼저 `parts/1-basics.html`의 `p1-fwl` 소절을 처음부터 끝까지 읽고 이번에 추가한 방식(유도 단계, 기호 태그, 긴 형식 표, 도식 안내 문장)을 본보기로 삼는다. 완성된 화면은 `presentation/20261118-guide/index.html#p1-fwl`.

## 1. 맡은 범위와 파일

- 맡은 조각 `parts/N-*.html`, 기호 풀이 파일 `parts/gloss-N.html`(새로 만든다), 도식 파일 `viz-pN.js`만 수정한다. 4부와 5부를 맡은 작성자는 `viz-p4.js`, `viz-p5.js`를 새로 만들어도 된다(빌드가 있으면 자동으로 불러온다).
- 공용 파일(viz-math.js, viz-kit.js, widgets.js, guide.css, build.mjs, gloss-1.html, 다른 조각)은 고치지 않는다. 필요하면 보고에 적는다.
- 기존 내용은 지우지 않는다. 압축된 문장을 풀어 쓰거나 그 뒤에 단계를 덧붙인다. 소절 id, href, data-* 속성, 덱 링크는 바꾸지 않는다. 새 소절이나 h4를 더해도 된다(id는 `pN-` 접두사).
- 커밋, 푸시, 배포는 하지 않는다.

## 2. 새 도구

### 2-1. 기호 태그와 풀이 툴팁

- 수식 안에서 `\gl{키}{식}`으로 기호에 키를 단다. 예: `\gl{att}{ATT(g,t)}`, `\gl{mu}{\mu_{g,\ell}}`. 빌드가 `<span class="tk k-키">`로 만든다.
- 키의 설명은 `parts/gloss-N.html`에 쓴다. 형식은 `parts/gloss-1.html`을 그대로 따른다.
  ```html
  <dl class="gloss">
  <dt data-k="att"><tex>ATT(g,t)</tex> 코호트-시점별 평균처치효과</dt>
  <dd><p>설명 (문서 문체 규칙 그대로).</p><span class="ex">예: 덱 19장 값 …</span></dd>
  </dl>
  ```
  dt에는 기호와 짧은 이름, dd에는 2-4문장 설명과 선택적으로 `<span class="ex">` 예시 한 줄. 키는 영문자와 숫자만(첫 글자 소문자 권장). 다른 gloss 파일과 키가 겹치면 빌드 보고의 `glossDup`에 나온다. gloss-1.html의 키(아래)는 다시 정의하지 말고 그대로 쓴다.
  `Y D G ai lt d dhat eps tau tauE2 tauE3 tauL3 Dbi Dbt Db Dhat Dtil w sum sumt sumi T X1 X2 X1hat X1til b1 b2 c e num den numD denD`
- `\gl`을 하나도 쓰지 않은 수식에는 빌드가 자주 나오는 기호(D_{it}, Y_{it}, \alpha_i, \lambda_t, \delta, \tilde D, \bar D_i 등)에 자동으로 태그를 단다. `\gl`을 하나라도 쓴 수식은 자동 태그를 하지 않으므로 필요한 기호를 모두 직접 단다.
- 독자가 처음 보는 기호가 나오는 **핵심 별행 수식**은 `<div class="sym"><tex class="d">…</tex></div>`로 감싼다. 수식 아래에 기호 단추 줄이 생겨 휴대폰과 키보드로도 설명을 열 수 있다.
- 표나 도식의 HTML 요소에 `data-k="키"`를 달면 그 요소에 마우스를 올릴 때 같은 절 안의 같은 키 기호가 함께 강조된다(툴팁은 뜨지 않는다).
- 주의: `\hat\gl{…}`처럼 악센트 명령 바로 뒤에 `\gl`을 두면 KaTeX가 해석하지 못한다. `\gl{k}{\hat\beta}`처럼 악센트까지 감싼다. `&`(정렬)와 `\\`(줄바꿈)는 `\gl` 밖에 둔다. 수식 안에 `<`, `>` 대신 `\lt`, `\gt`.

### 2-2. 유도 단계 (항이 자리를 옮기는 애니메이션)

```html
<div class="deriv" data-title="무엇의 유도인지 한 줄">
<div class="ds"><tex class="d">…1단계 식…</tex><p class="dc">이 단계에서 무엇을 했는지 1-3문장</p></div>
<div class="ds"><tex class="d">…2단계 식…</tex><p class="dc">…</p></div>
</div>
```

- 다음을 누르면 **같은 키를 가진 항이 이전 단계의 자리에서 새 자리로 옮겨 가고**, 새로 생긴 항은 잠깐 붉게 표시된다. 키가 같으면 내용이 달라도 한 항에서 다른 항으로 변형된다(예: `\gl{z1}{\sum_t D_{it}}`가 다음 단계에서 `\gl{z1}{T\bar D_i}`로).
- 대응은 **맨 바깥 태그**끼리만 한다. 덩어리째 옮기고 싶은 부분(분자 전체 등)은 바깥을 한 키로 감싸고 안쪽 기호에도 `\gl`을 달아 툴팁을 유지한다: `\gl{num}{\sum \gl{X1til}{\tilde X_1}\gl{Y}{Y}}`.
- 같은 키가 한 단계에 여러 번 나오면 나온 순서대로 대응한다. 순서를 바꾸고 싶으면 키에 꼬리를 단다(`\gl{Dbi-a}{…}`): 툴팁은 앞부분 `Dbi`로, 대응은 전체 키로 한다.
- 설명이 필요 없는 덩어리 키는 `z`와 대문자나 숫자로 시작한다(`zA`, `z1`, `zNum`). 툴팁이 없고 빌드 경고에도 나오지 않는다.
- 단계는 3-8개. 각 단계는 한 가지 조작(대입, 합을 나누기, 상수를 합 밖으로, 0인 항 지우기, 양변 나누기)만 한다. 0이 되는 항은 한 단계에서 `\underbrace{…}_{=\,0}`로 보여 주고 다음 단계에서 지운다.
- `.dc` 설명에는 그 조작의 **이유**를 쓴다(OLS 기초만 아는 독자 기준). 수식 렌더용 `<tex>` 사용 가능.
- 상자 아래 "모든 단계 펼치기"로 전체를 한눈에 볼 수 있다. 자동 재생과 속도 단추는 기존 도식과 공유한다.

### 2-3. 도식 (기존 방식 그대로)

`VIZSPEC.md`의 규칙을 그대로 따른다. `GV.stepper`, `GV.frame`, `GV.seg`, `GV.slider`, `GV.to`, `GV.count`. 이번에 추가된 것:
- `GV.frac(x)`: 분모 72 이하 유리수를 `−7/6` 같은 문자열로.
- HTML 표가 더 맞는 도식은 `stepper`의 `init(svg, F)` 안에서 `svg.replaceWith(div)`로 바꿔 쓴다(본보기: viz-p1.js의 `panel-resid`). 끌어서 조작하는 도식 본보기: `ortho-proj`.
- 새 도식은 꼭 필요한 곳에만(맡은 부에서 1-3개). "글로 세 번 읽어도 머릿속에 그림이 안 그려지는 곳"이 기준이다. 장식, 그라디언트, 그림자, 둥근 카드 금지. 색은 CSS 변수만.

## 3. 무엇을 고칠지 찾는 법

맡은 조각을 처음부터 끝까지 **OLS와 2×2 DID만 아는 독자의 눈으로** 읽는다. 다음에 해당하는 곳을 모두 목록으로 만든 뒤 중요한 것부터 고친다.

- 수식이 이전 식에서 "정리하면", "대입하면", "~이므로"로 바로 넘어가는 곳 (유도 단계로 푼다)
- 정의되지 않았거나 다른 절에서 정의된 기호, 약어 (기호 태그와 풀이, 또는 첫 등장 자리에서 풀어 쓰기)
- 회귀식에 들어간 변수가 실제 자료에서 어떤 열인지 상상해야 하는 곳 (긴 형식 표나 작은 수치 예)
- 추정량의 절차(평균을 구하고, 비교집단을 정하고, 가중평균한다)가 문장으로만 있는 곳 (작은 표로 한 번 손계산)
- 통계 개념(표준오차, 군집, 기각률, 신뢰구간, 사전추세 검정, 가중평균의 가중치)이 OLS 기초 밖인 곳 (2-4문장 보충 또는 접는 질문 `details.qa`)
- 그림을 말로 설명하는데 그림이 없는 곳

고친 뒤에는 그 수식이나 문장이 **여전히 원문과 덱의 내용과 맞는지** 확인한다. 수치는 모두 출처가 있어야 하고 손계산은 `node`로 `../_src/20261118/stats.js`, `simcore.js`를 불러 다시 계산한다(SPEC.md 3절). 원문 PDF: 과목 폴더의 `literatures/Week 10 (2026-11-18)/How much should we trust staggered difference-in-differences estimates (2022).pdf` (Read 도구 pages로).

SPEC.md 3절과 STYLEPASS.md를 그대로 지킨다. 특히 em대시, en대시 0개(하이픈만), 가운뎃점 나열 금지(쉼표), 본문 화살표 금지, "A가 아니라 B" 습관 대구 금지, 제목에 콜론 금지, 구어 동사 금지(쏠리다, 꼽다, 매기다, 거치다, 드러나다, 치우치다, 곱해, 훑다, 뽑다, 골라, 빼고, 살짝 / 쓰다는 사용하다로), 연결어미 뒤 쉼표 최소화, 격식 평서체 "~다", 학술 어휘. 전문 학술 용어의 영어 병기는 괜찮다. 끝나면 `python3 tools/stylecheck2.py parts/N-*.html`로 점검한다(이 폴더 기준).

## 5. 빌드와 점검

- 빌드는 **자기 전용 출력 폴더로** 한다. `web` 폴더에서
  `GUIDE_OUT=presentation/20261118-guide-tmpN node presentation/_guide/build.mjs` (N은 맡은 부 번호).
  보고의 `texErr`는 0개, `glossMissing`에는 내가 쓴 키가 없어야 한다(다른 작성자의 키는 그쪽이 채운다).
- 화면 확인: `node presentation/_guide/tools/shot.mjs "file://<web 절대경로>/presentation/20261118-guide-tmpN/index.html" <스크래치패드>/shots '<명령 JSON>'`.
  명령 예: `[{"scroll":"#p2-es"},{"shot":"es-top"},{"click":"#p2-es .deriv .vb.pri","times":3,"gap":900},{"shot":"es-deriv","sel":"#p2-es .deriv"}]`. 출력의 `ERRS`는 `[]`이어야 한다. 찍은 PNG를 Read로 열어 눈으로 확인한다(글자 겹침, 넘침, 수식 깨짐).
- 끝나면 자기 tmp 출력 폴더를 지운다(`rm -rf presentation/20261118-guide-tmpN`).
