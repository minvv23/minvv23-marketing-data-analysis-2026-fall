# 독해가이드 문체 재점검 지침 (윤문 작성자용)

사용자 지적(2026-11-16): "AI식-한국어-표현.md 말투들 여전히 꽤 남아있는 거 같은데 한 번 더 점검." 지난 점검은 대시, 가운뎃점, 화살표, 일부 구어 동사만 기계로 확인했다. 이번에는 매뉴얼 전체(`[For Coding Agent] Hunnae Knowledge Warehouse/AI식-한국어-표현.md`, 특히 §1, §5-3, §5-4, §6-1, §6-3, §6-6, §6-6-1, §6-9, §6-11, §6-12)를 기준으로 **문장을 직접 읽고** 고친다. 검출 스크립트는 후보를 찾는 도구일 뿐이다.

## 1. 문서의 성격과 register

- 이 가이드는 "11월 18일 발제를 더 풍부하게 이해할 수 있게끔 돕는 자료"다(사용자 문장). "발표자 한 사람을 위한", "발표자 본인", "나만을 위한" 같은 독자 지정 표현은 지우거나 중립적으로 바꾼다. 4부(장별 발표 가이드)와 "발표에서는" 상자처럼 발표 자체를 다루는 내용은 그대로 둔다.
- register는 **해설형 학술 문서의 격식 평서체("~다")**. 번역투 없는 격식체가 목표다. 구어로 내려앉지 않게 하고(§6-6), 반대로 "-했다"를 "-하였다"로 일괄 올리는 격식 과잉도 하지 않는다(§6-9 ④).
- "발표에서는" 상자 안은 발표체("~습니다")를 유지하되 같은 기준으로 AI 말투를 점검한다.

## 2. 우선 교정 대상 (검출 수가 많은 순)

| 유형 | 매뉴얼 | 처리 |
|---|---|---|
| 연결어미 뒤 쉼표 ("~하며, ~하고, ~면, ~지만, ~는데,") | §6-1 (한국어 AI 최강 단서) | 쉼표 없이 읽히면 지운다. 목표: 절반 이상 감축. 문장 사이 논리를 쉼표로 잇지 말고 어미로 잇는다 |
| 강조 따옴표 | §6-9 ③ | 실제 인용(원문, 덱 화면 문구, 대본, 질문 예시)과 고유 라벨은 유지. 강조용 따옴표는 지운다 |
| 구어 동사 (절차, 수치) | §6-6, §6-6-1, §6-11 ④, §6-12 ④ | 쓰다→사용하다, 고르다/뽑다→선택하다/선정하다, 빼다→제외하다/차감하다, 넘다→초과하다/상회하다, 거의→대부분/뚜렷하게 ~않다, 훨씬→상당히/현저히, ~라는 뜻이다→~을 의미한다, 어느 쪽→어느 집단/어느 추정치, 내려가다/올라가다→하락하다/상승하다, 섞이다→혼재하다/포함되다. 분야 관용어("차감한다", "~에 그쳤다")는 유지 |
| 문두 접속어 | §1-2, §6-9 ③ | "또한, 즉, 이처럼, 따라서, 한편, 그리고, 하지만, 결국, 이를 통해, 이러한"으로 여는 문장을 줄인다. 논리 관계가 사라지면 남긴다. "즉"은 부당 2회 이하 |
| 완곡 종결 | §1-4, §5-2 | "~할 수 있다, ~셈이다, ~것으로 보인다, ~라고 할 수 있다". 사실이면 단정한다. 진짜 가능성이면 유지(서법 보존, §6-9 ④) |
| 당위 결말 | §6-9 ② | 문단이 "~해야 한다, ~할 필요가 있다"로 끝나면 당위 문장을 지우지 말고 문단 앞, 중간으로 옮긴다 |
| 중요성 부풀리기, 과장 | §5-1, §5-4 ⑥ | "핵심은, 가장 중요한, 주목할 만하다, 매우, 정말, 완벽하게, 결정적". 근거가 없으면 지우고, 있으면 근거를 쓴다 |
| 부정 후 재정의, 대조 | §6-9 ② | "X가 아니라 Y", "~이 아니다. ~이다", "단순히 ~이 아니라", "X를 넘어 Y", "X에서 Y로". 대부분 Y만 쓰면 된다. 오해를 바로잡는 실질 대조(질의응답의 오해 교정 등)는 공식 없이 평서로 쓴다 |
| 번역투 | §1-1 | "~에 대해/에 대한"이 "을/를"로 되면 바꾼다. "~을 가지고 있다"→"~이 있다". "~에서의, ~로의"→풀어 쓴다. "그것은" 대명사 생략 |
| 삼단 병렬, 3박자 "A, B, 그리고 C" | §2-2, §6-3 | "그리고 C"는 "A, B, C" 또는 "A와 B, C"로 |
| 문단 첫 문장의 넓은 맥락, 예고형 도입, 프랙탈 요약 | §5-4 ⑤, §6-3 | "이 절에서는 ~를 살펴본다", "앞에서 본 것처럼"이 반복되면 줄인다 |
| 리듬 | §1-7, §6-9 ② | 단문만 늘어놓지 않는다. 100자 이상의 긴 문장도 자연스럽게 섞는다. 같은 종결("~이다.")이 연속되면 일부 바꾼다 |
| 수식어 반복 | §6-11 ① | 정의된 용어(문제 소지가 있는 비교, 아직 미처치 등)는 고정. 대상을 꾸미는 설명적 수식어가 반복되면 풀어 쓴다 |

## 3. 바꾸지 않는 것

- 전문 학술 용어의 영어 병기(사용자 지시, 2026-11-16: "전문 학술용어 병기는 전혀 문제가 아녀"). 매뉴얼 §6-3, §6-11 ⑥의 영어 병기 항목은 이 문서에 적용하지 않는다.
- 수치, 수식(`<tex>` 안), 표의 값, id, href, data-* 속성, 마크업 구조, 덱 링크, 그림. 사실관계와 서법(단정, 추측, 당위의 구분)을 바꾸지 않는다.
- 원문, 덱 화면, 대본에서 그대로 옮긴 인용문(따옴표 안). 사용자가 직접 쓴 문장(0부 첫 문장).
- 변경률은 문단 기준 대략 5-30%. 내용을 새로 쓰지 않는다. 같은 금지어를 대체어 하나로 일괄 치환해 새 반복을 만들지 않는다(§6-11 ③). 교정 뒤 새로 넣은 단어 빈도를 센다.

## 4. 절차

1. 맡은 파일의 원본을 스크래치패드에 복사해 둔다.
2. `python3 tools/stylecheck2.py <파일>`(이 폴더 기준)로 후보 목록과 유형별 수를 기록한다.
3. 파일 전체를 처음부터 끝까지 읽으며 고친다. 검출되지 않은 AI 말투(문단 첫 문장, 리듬, 추상명사, 근거 없는 정리 문장)도 고친다.
4. 다시 `stylecheck2.py`를 돌려 전후 수를 비교한다.
5. 무결성 확인: 원본과 수정본의 `<tex>…</tex>` 목록, `id="…"`, `href="…"`, `data-…` 목록이 같은지 스크립트로 비교한다. 태그 짝이 맞는지 확인한다. JS 파일은 `node --check`.
6. `build.mjs`는 돌리지 않는다(동시 실행 시 출력 폴더가 지워진다). 조립과 전체 점검은 조립자가 한다. 커밋, 배포하지 않는다.
